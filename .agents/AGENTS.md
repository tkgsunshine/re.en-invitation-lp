# Re.en（リエン）開発・運用・コンテンツ・SEO 統一レギュレーションガイド

本ドキュメントは、Re.en（既婚者限定完全審査制マッチングLP）におけるデザイン、コンテンツ制作、SEOキーワード戦略、本質的コンテンツ編集方針、技術・ビルドパイプラインに関する全決定事項・運用ルールを整理した公式レギュレーションです。

---

## 1. SEOキーワード選定戦略 (SEO Keyword Strategy)

コラム記事のキーワード選定は、単なるランダムな記事作成ではなく、検索エンジンの構造とユーザーの検索意図（Search Intent）に基づいた**「3層トピッククラスター戦略」**に従って厳密に設計・選定する。

```
        ┌─────────────────────────────────────────┐
        │  1. ピラーキーワード (ビッグワード)        │
        │  「既婚者マッチング」「セカンドパートナー」  │
        └────────────────────┬────────────────────┘
                             │ (内部リンク集中)
        ┌────────────────────┴────────────────────┐
        │  2. ミドルキーワード (検討・比較)         │
        │  「既婚者アプリ 審査」「既婚者マッチング 料金」│
        └────────────────────┬────────────────────┘
                             │ (評価の底上げ)
        ┌────────────────────┴────────────────────┐
        │  3. ロングテールキーワード (悩み・潜在ニーズ)│
        │  「40代既婚女性 心境」「既婚者 お茶デート マナー」│
        └─────────────────────────────────────────┘
```

1. **ピラー（Pillar）キーワード［ビッグワード / 難易度：極高］**
   - 対象ワード: 「既婚者マッチング」「既婚者アプリ」「セカンドパートナー」
   - 役割: サイト全体の主題を宣言し、最終的なコンバージョン（事前登録）を獲得する。

2. **ミドル（Middle）キーワード［検討・比較ワード / 難易度：中〜高］**
   - 対象ワード: 「既婚者マッチングアプリ おすすめ」「既婚者アプリ 審査」「既婚者アプリ 安全」
   - 役割: サービス検討層を引き込み、Re.en の強み（完全審査制・ハイクラス・身バレ防止）を直接訴求する。

3. **ロングテール（Long-tail）キーワード［悩み・潜在ニーズワード / 難易度：低〜中（即効性高）］**
   - 対象ワード: 「40代既婚女性 マッチングアプリ」「既婚者 お茶デート 服装」「既婚者サードプレイス」
   - 役割: 検索意図が極めて明確な悩めるユーザーを狙い撃ちし、初速の検索上位（1ページ目）を獲得してドメインパワーを底上げする。

4. **検索意図（Search Intent）4分類の網羅**
   - **Know（知りたい）**: 「セカンドパートナーとは」「既婚者の心理」
   - **Do（解決したい）**: 「既婚者 デート 誘い方」「身バレしない設定」
   - **Go（探したい）**: 「既婚者アプリ おすすめ」
   - **Buy（登録したい）**: 「Re.en 審査」「Re.en 評判」

## 2. 本質的コンテンツ編集戦略 (Editorial Strategy)

ただ検索順位を上げるだけでなく、**「記事を読んだユーザーが深く感銘を受け、自発的に Re.en の創設メンバーに登録したくなる」**ための本質的な執筆・編集戦略を徹底する。

1. **カスタマージャーニーと感情移入（Emotional Storytelling）**
   - ターゲット読者（社会的ステータスを持つ30〜50代既婚男女）の「誰にも言えない孤独感」「配偶者への感謝と申し訳なさ」「自分らしさを取り戻したい本音」に寄り添うストーリー設計を行う。

2. **Re.en 独自の強み（USP）への文脈的接続（Contextual CTA）**
   - 記事内で「一般のマッチングアプリで発生する身バレのリスクや質の低さ」という課題を提示し、**「だからこそ、完全審査制・写真ぼかし標準対応・社会的ステータスを備えた Re.en が必要なのだ」**という必然的な納得感を作る。

3. **E-E-A-T（経験・専門性・権威性・信頼性）の担保**
   - 心理学的考察（承認欲求、サードプレイス理論）や大人のマナー・倫理観・安全対策を盛り込み、プロメディアとしての高い信頼性を構築する。

## 3. コンテンツ制作レギュレーション (Content Standard)

1. **文字数と内容の深さ (Volume & Depth)**
   - **文字数規定**: 1記事あたりの**純記事本文（pタグ文章）は 2,500〜3,500文字以上（HTML全体で5,000文字以上、読了目安5分以上）**とする。
   - 単なる抽象的要約（Thin Content）は不可。具体的心理分析、リアルな事例、会話フレーズ、注意点を網羅すること。

2. **記事構造と目次 (Structure & Table of Contents)**
   - **目次設置義務**: リード文（`<p class="article-lead">`）の直後に、階層構造化された「目次（`<div class="article-toc">`）」を必ず自動生成・配置すること。
   - **見出し階層**: H2見出しの中に必ず 2〜3 個の H3 小見出しを配置する。
   - **アンカーID**: H2およびH3見出しには一貫したID（`id="heading-1"`, `id="heading-1-1"`）を付与し、スムーズスクロール（`scroll-behavior: smooth`）でジャンプ可能にすること。

3. **必修コンテンツ要素 (Mandatory Sections)**
   - **ケーススタディ**: 各記事に「【ケーススタディ】具体的成功例・気づき」を挿入すること。
   - **NG行動リスト**: 「避けるべき注意点・NG行動のチェックリスト」を箇条書きで掲載すること。
   - **記事内CTA**: 記事下部に Re.en 創設メンバー（2ヶ月無料優先インビテーション）への専用案内ボックス（`<div class="in-body-cta">`）を配置し、`preregister.html` へ誘導すること。

## 4. SEO＆テクニカルレギュレーション (SEO & Technical Standard)

1. **全ページ必須メタタグ**
   - `<title>`: ページ毎にユニークかつキーワード最適化。
   - `<meta name="description">`: 100% 全ページに個別の説明文を設定（欠落ゼロの維持）。
   - `<link rel="canonical" href="https://re-en.jp/...">`: 全ページ必須。
   - `<h1>`: 1ページに必ず1つ設置（ロゴまたは見出し）。

2. **OGP & Social Meta Tags**
   - 全ページに `og:title`, `og:description`, `og:type`, `og:url`, `og:image`, `og:site_name`, `twitter:card="summary_large_image"`, `twitter:title`, `twitter:description`, `twitter:image` を完全設置すること。
   - コラム詳細ページの場合、`og:image` には該当記事のサムネイル画像（例：`https://re-en.jp/images/column_X.webp`）を指定すること。

3. **構造化データ (JSON-LD)**
   - コラム詳細ページには `BlogPosting` および `BreadcrumbList` の JSON-LD スキーマを必ず挿入すること。
   - トップページ・料金・コラム一覧には `WebSite`, `Organization`, `FAQPage` スキーマを維持すること。

4. **404エラー対策**
   - ブランドデザインに合わせた `404.html` を常設し、サイト訪問者の離脱を防止すること。

5. **robots.txt & sitemap.xml**
   - `robots.txt` で `Sitemap: https://re-en.jp/sitemap.xml` を明記。
   - `sitemap.xml` に全66コラムおよび全固定ページを漏れなく網羅・自動更新すること。

## 5. デザイン＆UI/UXレギュレーション (Design & Layout Standard)

1. **スマホ・ヒーローエリア配置**
   - スマホ画面において、背景画像（女性の顔）にメイン見出しが重ならないよう配置を固定する（`.hero__headline` `margin-top: 420px !important;`）。
   - 上部3つのタグバッジ最下部が、背景画像の最上部エッジとぴったり接するレイアウト（`.hero` 背景位置 `center 118px`）を維持すること。
   - 背景画像の上部フェード（黒グラデーションオーバーレイ）は完全に排除すること。

2. **リンク統一**
   - 事前登録・無料インビテーションリンクは、すべて `preregister.html` に統一すること（`href="/register"` 等の404ルーティングエラーの発生を完全防止）。

---

## 6. ビルド・デプロイ・自動化パイプライン規約 (Deployment & CI/CD Standard)

1. **Vercel バッチデプロイの徹底 (Batch Deployment)**
   - Vercel の1日100回デプロイ制限を回避するため、複数ファイルや一括修正の作業は**「たった1回の Git Commit & Push ＋ 1回の Vercel 一括デプロイ（npx vercel deploy --prod）」**にまとめること。個別の細切れデプロイは厳禁。

2. **GitHub Actions クラウド自動定時配信 (Cloud Automation)**
   - 毎朝10:00 JST のコラム自動更新・公開は、ローカル Mac のスリープやキーチェーン認証エラーの影響を受けないよう、**GitHub Actions サーバーサイド（`.github/workflows/daily_column.yml`）** で自動実行すること。

3. **スクリプトの環境独立性**
   - パイプライン用スクリプト（`run_matching_column_pipeline.py` 等）は、実行場所を問わないよう動的パス（`os.path.dirname(os.path.abspath(__file__))`）を使用すること。

---

以上のレギュレーションをプロジェクトの絶対原則として遵守し、継続的な運用・機能拡張を行います。
