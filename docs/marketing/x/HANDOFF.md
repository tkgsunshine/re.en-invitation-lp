### 投稿のDB（`reen_x_posts`）の項目
`id`, `order`（小さいほど上。小数可）, `theme`, `text`, `replyText`（リプ欄に貼る文。任意）, `editedText`, `status`（`draft`確認待ち／`ready`投稿待ち／`posted`／`dropped`）, `utm`, `created`, `decidedAt`, `postedAt`。
- 新しい案は、`status: "draft"` で追加する。承認・投稿済みの記録は、ユーザーがホームで押す。
- **承認前の本文を、勝手に直さない。** ユーザーが承認・編集した文は、勝手に変えない（変えたら伝える）。
- **書き込みは `if_version` が必須。** ユーザーや他のセッションが、同時に書き換える。版が合わないと失敗するので、読み直して再実行する。1回のバッチは50件まで。

## 3. 投稿の方針（`strategy.md` が正。要点のみ）
- 1日3本。**時間帯は決めない**（空いた時間に投稿）。
- 1日1本は **MBTIランキング**（固定）。残り2本を、4種類に均等に回す（各25%）:
  1. 場面＋見立て＋問い（場面→一言の見立て→開いた問い。リプを集める）
  2. 既婚者あるある（問いは付けない。言い切り）
  3. 深い系（婚外恋愛・夫婦の見立て。目から鱗の型。問いは付けない。別セッションが2026-10-24に追加）
  4. コラム紹介（本文のみ。リンクは末尾。リプ欄は使わない）
- 口調: コラム紹介と婚外恋愛は「です・ます」。場面・あるあるは、現状のまま（ユーザーの指示なし。必要なら確認する）。
- 禁止: Re.enの説明・機能紹介・募集の投稿（今は出さない）／実在の体験談風の書き方（「私は」「ある会員が」）／出典のない権威づけ（「専門家によると」など）／統計・数字の捏造／配偶者や家族を欺く方法／婚外恋愛を勧める・批判する書き方／ハッシュタグ。
- 文字数: Xの重み付きで280以内（全角=2、半角=1、URL=23、改行=1。①▼｜なども全角扱い）。
- 問いの作り方: 番号で答える選択式は不可（反応がなかった）。場面に紐づいた開いた問い。

### MBTIランキング（毎日1本）
- 形（月と蓮と同じ）: 本文＝「〇〇な16タイプ（MBTI）」＋3位〜14位（「3位 INTJ 建築家」の形）＋「1位・2位と15位・16位は、リプ欄に。」／リプ欄＝1位・2位・15位・16位＋「あなたは何位でしたか？」＋「Re.enでは、プロフィールにMBTIを載せられます。」＋「▼Re.en」＋ `https://re-en.jp/?utm_source=x`。
- お題: 既婚者の恋愛・婚外恋愛（ときめき・割り切り・一途・後ろめたさ・承認・打ち明けられない・深入り）。
- **順位は編集部の見立て（根拠データなし）。** 「統計」「調査」「データ」とは書かない。注記（「編集部の見立てです」）は、ユーザーの指示で入れない。
- 16タイプの日本語名: INTP論理学者／ISTJ管理者／INFJ提唱者／ENTJ指揮官／ESTP起業家／ISFJ擁護者／ESTJ幹部／INFP仲介者／ENTP討論者／ISFP冒険家／ENFJ主人公／ESFJ領事官／INTJ建築家／ISTP巨匠／ENFP運動家／ESFP エンターテイナー。
- 「Re.enはプロフィールにMBTIを載せられる」は、ユーザーが述べた事実（コードでの確認はしていない）。これ以上の機能の主張を足さない（「気が合う人と出会える」等は、確認できていないので削除済み）。
- 在庫: m01〜m07（1週間分）。m02は投稿済み。**来週分のお題を追加する必要がある**。

## 4. 返信・フォロー
- 返信は、他人の投稿への返信が主（目安15〜30件／日、上限30、連続10件以上はしない）。フォローは10〜30人／日（上限30）。
- 返信案の作成: ホームの「貼って返信案を作る（Re.en）」。ページの `window.claude.use("sample")` を使う。指示文は、ホームのHTML内の `REEN_REPLY_RULES`、検査は `reenDraftProblems`。
  - 現行ルール: 全角60〜140字（上限170）、2〜3文、です・ます調、共感＋理由＋格言ふうの一文（出典を偽らない）、問いかけ案は80字以上の開いた問い、宣伝・URL・「Re.en」の名前・DM誘導は禁止、運営の個人体験風の言い方は禁止。5案（共感2・視点・問いかけ・相づち）。
- フォロー対象（`follow.md`）: ライフスタイル系・大人の恋愛や夫婦関係の発信者など。出会い目的・不倫の誘い・成人向け・詐欺（美人局など）のアカウントは避ける。フォロワーに詐欺系が増えたら、ブロックでよい（フォロワー数は減る。大量ブロックの後、一時的にタイムラインが見られなくなった事例がある）。

## 5. 計測
- Xのアナリティクス（無料はポスト単位のみ）＋ Vercel Web Analytics（Referrersの `t.co`）。投稿別の計測はしない方針（Xからの流入かどうかだけ）。UTMタブは有料で使えない。
- 毎週日曜: 表示回数・プロフィール訪問・リンククリック・`t.co` を、チャットで共有してもらい、戦略を更新する。
- 検証したい仮説（未検証）: リンク付き投稿は表示されにくいか／MBTIランキングが拡散に効くか／婚外恋愛の話題が詐欺アカウントを呼ぶ度合い。

## 6. ホームのHTMLを直すとき（手順）
1. `Artifact` の `read`（`url` 指定）で、最新を取得する（4MB超。全文は読まず、保存先ファイルの必要な行だけ読む）。
2. 保存ファイルを作業用にコピーして直し、同じURLに `publish`（同じ `file_path`）。小さな変更は `edits`（old_str/new_str）で可。
3. 他のセッションも、同じページを更新する。公開が拒否されたら、最新を読んで、変更を載せ直す。
4. 「X Re.en」タブの外（月と蓮・SEO日報・開発日報など）は、触らない。

## 8. 引き継ぎ時の注意（実際に起きたこと）
- ユーザーや別セッションが、同時にDBを書き換える（承認・投稿済みの記録、深い系の追加など）。**書く前に必ず、読み直して現状を確認する。** 古い想定で並べ替えを書くと、全件失敗する（バッチはまとめて失敗する）。
- 説明は、事実と推測を分けて書く。確認できていないことは、断定しない（過去に、有料機能を使えると誤って案内した）。
- ユーザーの指示は、短い。意味が複数に取れるときは、取った意味を明記して進め、違っていたら直す。
